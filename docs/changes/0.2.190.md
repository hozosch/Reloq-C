# 0.2.190

- Parsed pronunciation dictionaries now survive a cancelled or failed native
  analysis machine. The obsolete machine links and its dictionary undo text
  are detached; the worker keeps its tables and lexical data until a new
  dictionary snapshot is selected or the language owner is closed. Building
  a replacement dictionary remains transactional. Speech results are not cached.
- The previous version already retained tables during uninterrupted speech,
  but discarded them along with an interrupted machine. This forced the full
  US dictionary to reload on the next request. A local six-cycle comparison
  reduced median time to first PCM after cancellation from about 207 to 24 ms.
  All complete PCM hashes, lengths and indices matched. This is a host-core
  measurement, not a Windows/NVDA device timing; the first dictionary load
  still has a cost.
- Repeated notifications for the same immutable dictionary snapshot no longer
  reinitialize already loaded languages. Editor changes and community updates
  still produce a new snapshot and activate its entries.
- Android `0.2.190-preview2` fixes the install-blocking packaging error in
  preview 1. Repacking had compressed `resources.arsc`; aapt2's storage methods
  are now preserved. A separate final-APK check verifies the stored resource
  table, four-byte data alignment and ARM64 ELF alignment. The actual previous
  APK fails the new check and the replacement passes. Package name and the
  preview signing certificate stay the same.

The new retention regression removes its test-owned source dictionary after
loading. It checks 18 cancellation, callback-failure, profile, failed-update,
new-entry and disable cases without allowing an accidental reload to go
unnoticed. Version 0.2.189 fails the first cancellation case. The modified
provider also passes AddressSanitizer with the private arena instrumented;
LeakSanitizer is disabled in that development run.

Native dictionary semantics, queued reload/cancel recovery at 48 kHz, language
PCM/index comparisons, both NVDA UI languages and the Android JNI streaming
comparisons remain checked. Actual Pixel installation/TalkBack playback and
the user's remaining responsiveness assessment are still outstanding.
