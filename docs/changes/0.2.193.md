# 0.2.193

- NVDA and Android expose separate **Use abbreviation dictionary** and
  **Phrase prediction** settings. Abbreviations remain enabled by default;
  prediction remains disabled. The controls use the native environment and
  do not require ECI command processing. Main and Root pronunciation volumes
  remain active independently of abbreviation expansion.
- The ECI interface accepts abbreviation control at parameter 3, with native
  ECI polarity: 0 enables it and 1 disables it. Parameter 11 provides the
  per-instance phrase-prediction control, 0 off and 1 on. Invalid values are
  rejected. Settings are scoped to each engine/request and survive normal
  worker reuse without reloading pronunciation dictionaries.
- German retains its independent acoustic planner. Native phrase prediction
  now contributes its selected word boundaries as well as its word accents.
  The native insertion point is aligned with the following SPR word; no
  word-count heuristic or alteration of the caller's input text is used.
  A 25-word regression places the original inferred comma before word 12.
  Written punctuation, source indices and the accepted sound departures remain.
- German degree and underscore names are replaced directly in the native
  character rule and the admitted character table: **Grad** and **Unterstrich**.
  Ring accents in Å/å retain **Ringel**. The literal word Ringel is unchanged.
- Equal speed controls retain language-specific duration models. The reproducible
  [rate comparison](../validation/0.2.193-language-rates.json) renders six native
  /ma/ syllables at speeds 55 and 98, inflection 0, 11,025 Hz and two pause
  policies. At speed 55 with shortened pauses, German lasts 1.594 s, American
  English 1.411 s and Castilian Spanish 0.964 s. This measures output duration;
  it is not a CPU benchmark or an exact WPM calibration. French uses its own
  native SPR stress placement. Asian syllable inventories are excluded from
  this controlled comparison.
- The user confirmed Android 0.2.192, including immediate settings, as stable.
  Android 0.2.193 adds the shared engine changes and analysis settings. Its
  signed upgrade check confirms the same package/certificate and
  versionCode 20192 → 20193. The new controls still need the ordinary device
  listening test. SAPI5 remains planned; it is not implemented in this version.
- Community dictionaries were refreshed from master
  `f93ccc82158386f7607ed3868473b6914121d2d7`; all seven Git blobs are verified.
  The Chinese traditional-character correction from 0.2.192 remains: 38
  source identities in ambiguous simplification families, including 發/髮,
  隻/只, 臟/髒 and 癥/症, with contextual and neutral-tone readings retained.

Validation includes 189 native setting/tag/scope/fragment/index/character
comparisons, 40 language PCM/index comparisons, 366 CJK Latin comparisons,
35 JNI/direct-C PCM comparisons, 866 Android settings/data checks, 18 dictionary
retention cases, 25 native dictionary semantics cases and the complete ECI
regression target. The latter includes 1,680 Asian/Greek renders and 105 pause
comparisons. Both NVDA UI languages pass. Windows retains the 21-export ABI.
All speech tests keep PCM in RAM and create no audio files.

Parameter/inline-command equality is checked in the Western grammars. The
Asian and Greek romanizers retain their native parameter/command ordering;
API controls are checked separately there. No claim of equal ordering for
embedded English is made. Existing voice/language command behavior is retained.
There is no new runtime data file, bytecode, original DLL/SYN dependency,
speech-result cache or DSP change.
