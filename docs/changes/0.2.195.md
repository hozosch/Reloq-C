# 0.2.195

- German sentence analysis retains an entire hyphenated initialism when its
  native reading spans several phonetic words. Previously, reconstructing
  “NVDA-Einstellungen” duplicated its final A, so the context group counts
  disagreed and the whole sentence fell back to spelling analysis. This
  caused the wrong ch in “NVDA-Einstellungen: Sprachausgabe
  (Standard-Konfiguration)”. The fix applies to this source/group alignment,
  rather than adding a pronunciation exception for Sprachausgabe.
- The native phoneme interface can stream callback chunks directly to the
  requesting analyzer. Embedded NUL separators and cancellation/error recovery
  are retained. German context analysis grows its buffer with the actual
  output instead of reserving 32 times the input/annotation size. It releases
  reconstructed input before growing the final annotation, and uses one
  allocation for the two group maps. No utterance or PCM cache is introduced.
- Native language-rule translation units are compiled for size. The
  per-sample audio engine retains its existing optimization settings. Rules
  remain directly compiled C; there is no new decompressor, bytecode runtime,
  original module dependency or external service.
- The Android preview uses the same core changes. Package name, signing
  identity, settings and dictionary locations are retained for an in-place
  update from preview6.

The own German acoustic planner and documented sound departures remain.
Automatic cross-language rate normalization and SAPI5 are still pending.
Speech checks hash PCM in RAM and create no audio files. Host benchmarks do
not replace the ordinary NVDA/TalkBack listening check.

Build sizes, comparison results, resource measurements and artifact hashes
are recorded in the [validation report](../validation/0.2.195.json).

Compared with 0.2.194, the Windows DLL shrinks from 61,280,256 to 55,981,568
bytes (5,298,688 bytes, 8.65%). The NVDA download is 2,729,215 bytes smaller;
the APK is 114,688 bytes smaller. All languages and voices remain included.

Validation passes the complete native ECI suite, 196 bit-exact PCM/index
comparisons with 0.2.194 across 14 languages, seven rates and two models,
46 unchanged German word SPR readings, 227 analysis-option comparisons,
366 CJK Latin checks, 35 JNI/direct-C pairs and 866 Android settings/data
checks. Both NVDA UI languages and APK in-place upgrade verification pass.

The measured benefit in this build is file size. Paired Linux CPU timings
have a median ratio of 1.005 and individual ratios of 0.968 to 1.096, so they
do not establish a general speedup. The German long-text requested heap
peak is unchanged. Streaming reduces cumulative allocation requests by
805,120 bytes in the 4,000-word sample, but the larger acoustic planning
buffers remain an optimization target. These are requested heap bytes,
not process RSS.
