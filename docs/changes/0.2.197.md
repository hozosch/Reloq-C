# 0.2.197

- German sentence analysis keeps the source punctuation between words, before
  the first word and after the last word. Private acoustic continuation marks
  are no longer substituted for those grammar boundaries. Numeric hyphens such
  as `NVDA-2026` are not treated as suspended word constituents. Enclosed
  ellipses remain ellipsis prosody. These changes prevent reproduced cases
  from falling back to strong accents on ordinary function words.
- Rule-call tracing is compiled out of release builds across the language
  providers. Argument packing, mutable tracing state and per-call diagnostic
  tests remain available only in a separate development build with
  `RULE_DIAGNOSTICS=1`. Native rules and the existing acoustic paths remain.
- Android app updates open the validated GitHub release download in the
  browser. The app no longer requests `REQUEST_INSTALL_PACKAGES`, exposes an
  APK content provider or launches package installation itself. NVDA’s update
  flow is unchanged. No update check runs in the background or speech worker.
- Package name and signing certificate are retained for an in-place Android
  update. Published GitHub release assets are still needed before either
  update screen can offer a newer package.

The user reported a harmful-app classification from Play Protect for
0.2.196. Removing the added installer path reduces app permissions, but does
not establish the cause or prove that Google has cleared this build. The
compiled manifest, signed upgrade compatibility and native dependencies are
checked locally. Keep Play Protect enabled. Google’s
[developer guidance](https://developers.google.com/android/play-protect/warning-dev-guidance)
describes harmful-app classifications and the review route.

The Windows DLL decreases from 55,982,592 to 55,212,544 bytes. The NVDA
package saves 369,223 bytes and the APK saves 503,808 bytes. The unstripped
ARM64 library saves 1,601,416 bytes. Native dependency checks find only
platform C/math/loader/UI libraries, with no extra language runtime.

All 196 multilingual/rate/model PCM comparisons are bit-identical to 0.2.196.
The initial Linux CPU comparison has a median ratio of 0.971 (about 3% less
CPU), with mixed individual results. A focused follow-up after the other
builds/tests finish measures Spanish 11 kHz at 0.945 and German 48 kHz at
0.996. This is a modest analysis-path benefit; no meaningful high-rate DSP
speedup is established. The 4,000-word requested heap peak stays at
100,477,682 bytes. These are host measurements, not device latency or RSS.

The own German acoustic planner and documented pronunciation departures
remain. No speech-result cache, audio file, runtime bytecode, original
language DLL or additional third-party runtime library is introduced.
The full original Apple binary was not executed here; the analysis reference
is the existing complete native C rule provider. The user’s remaining
unidentified example cannot yet be verified directly.
