# 0.2.198

- German passes mixed identifiers and filenames as complete native source
  tokens. Splitting an alphabetic head from its digits changed acronym
  selection and could even change the pronunciation of a later word.
  Both `reloq-c-android-arm64-0.2.197-preview9.apk` and
  `SAPI5 berücksichtige ich bei der Vorbereitung des ersten Releases.` now
  match the complete native analysis. Real terminal punctuation is included
  when resolving context-dependent numeric components. Native German letters
  in identifiers are retained; other Unicode keeps its character-table path.
- The German acoustic planner grows private source-knot storage from actual
  use. It no longer reserves the combined worst-case capacities of six target
  streams. Knot ordering, cancellation and the separate acoustic target
  storage remain intact. No pronunciation or audio result is cached.
- High-rate filtering and spectral phase calculation have four-lane AVX2
  variants on supported native x64 processors. Each lane retains the old
  operation order and precision. Older processors and Windows x64 emulation
  on ARM keep the existing path. The 65-tap noise window is prepared once
  alongside the existing immutable transform constants; unity magnitudes
  bypass redundant logarithms. No new runtime library is required.
- The user reports that Play Protect accepts 0.2.197. Android retains that
  browser update flow, INTERNET-only permission profile, package identity
  and signing certificate. This preview updates the installed app.
- The [release plan](../RELEASE-PLAN.md) defines core checks and the remaining
  SAPI5 adapter work. SAPI5 is not implemented in this package.

The requested live heap peak in the 4,000-word German test decreases from
100,477,682 to 91,652,850 bytes, about 8.8%, at the same PCM output. This is
not a process RSS or device-memory measurement. The broad native C analysis
reference is the existing complete rule provider; no original Apple module
was executed in this workspace.

The quiet Linux AVX2 comparison reduces median 48-kHz CPU time by about
9.6% across the 14 languages. All 14 improve, by approximately 6.4–12.2%;
German improves by 6.4%, American English by 10.6%. The 11-kHz median is
essentially unchanged. All 196 language/rate/model PCM comparisons remain
bit-identical to 0.2.197. These are host CPU measurements, not device latency.

The extra x64 code increases the DLL by 10,752 bytes to 55,223,296 bytes.
The add-on is 1,721 bytes smaller, and the APK size stays at 17,708,438 bytes.
The benefit of this iteration is lower CPU and heap use. The large acoustic
target reservation and compiled language code/data remain optimization targets.

The own German acoustic planner and documented sound departures remain.
Tests keep PCM in RAM and write no audio files. CPU results, file-size
tradeoffs, artifact hashes and device-validation limits are recorded in the
[validation report](../validation/0.2.198.json).
