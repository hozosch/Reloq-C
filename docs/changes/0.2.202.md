# 0.2.202

SAPI keeps its initialized language between utterances. Previously the adapter
called `eciSetDictionaryPath` for every Speak, including unchanged or disabled
dictionaries; that operation deliberately reloads the language. The adapter now
checks native file metadata and reloads only when the selected folder or its
relevant .dic files change. Edits, creation, replacement and deletion still take
effect between utterances. No speech-result, repetition or PCM cache is used.

The ordinary SAPI speed scale follows SAPI5IBMTTS: native ECI speed is
`60 + 10 * (SAPI rate + XML rate adjustment)`, bounded to 0–250. Thus SAPI 0
selects ECI 60, and +10 selects 160. Optional speed boost multiplies the result
by 1.6 with a cap at 250; it is off by default. XML adjustments are bounded after
conversion, preserving the range above SAPI +10 and avoiding integer overflow.
The shared core now supports native speeds 0–39 as well. Its 80-byte duration
clock extension follows the native rule arithmetic; all 251 integer duration
percentages match that arithmetic. NVDA and Android keep their existing speed
slider mappings. Native zero has an explicit internal representation so it
cannot accidentally select the old developmental default.

There are separate native x86 and x64 SAPI packages. Both register one voice per
language, use the matching COM/Speech registry view and have separate engine
installations. They share user settings. The x86 core uses SSE2 scalar math and
the same undecorated ECI entry points; no bridging helper process is installed.
Basic operation of preview 1 on x64 was confirmed by the user. Preview 2 and its
new x86 installation still need real Windows client testing.

The sample rate always applies to every SAPI language. The engine advertises it
on output-format negotiation, allowing SAPI to convert to the client format.
Existing clients must renegotiate, reopen the voice or restart to adopt a new
rate. A checkbox optionally shares the remaining voice and dictionary settings.
Enabling it takes the current language's parameters; disabling it restores the
previous separate language settings. Both architectures use the same settings
format. The native dialog follows the supported Windows display language,
including Simplified/Traditional Chinese, and falls back to English. All valid
edits apply to the next utterance without a Save button.

The German pause sink now also compresses long exact-zero runs followed by a
late filter residual inside a planned source-silent interval. Every nonzero
sample and short zero crossing is retained. In the measured cases this removes
less than one millisecond. It does **not** establish a fix for the reported
perceptible extension of some short-pause releases. Phone lengths, release
curves and acoustic source levels were not changed for that report. Other
language modules shorten the native quiet body before rendering; the authored
German renderer preserves its full acoustic clock and removes PCM silence.

The shared core changes are also included in the NVDA and Android packages.
Android retains its existing package, signing certificate and in-place upgrade
path. The public release remains pending practical acceptance; this source
update does not publish GitHub binary release assets.

See the [SAPI guide](../../sapi/README.txt) and the
[validation report](../validation/0.2.202.json) for measurements, checks and
remaining device-test limits. Response measurements refer to the host transport
up to its first Write callback, not to audible Windows/device latency.
