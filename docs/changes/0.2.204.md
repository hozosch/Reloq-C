# 0.2.204

SAPI now synthesizes and writes on SAPI's own output thread, following the
reference adapter. The first native callback is delivered immediately;
subsequent callbacks use a bounded 4,096-sample live buffer. Events and
parameter boundaries flush it. The extra producer thread, semaphore handoff
and eight tiny packets have been removed. The selected native Eloquence rate
still belongs to the voice; conversion to the application's output rate is
left to SAPI. There is no custom resampler or speech-result cache.

A single Inno Setup installer installs x64 and x86 voices together on
compatible Windows, and x86 on 32-bit Windows. It offers twelve interface
languages, upgrades the same installation, and supplies a normal Windows
uninstaller. One dictionary folder and shared settings serve both COM views.
Edited dictionaries and per-user settings survive removal.

German shortened pauses now omit the planned quiet frames before synthesis,
like the other language planners. Original control curves, phone durations
and the full release remain on their original timeline. The live filter tail is allowed to settle through three complete silent frames; the remaining quiet body is then skipped. The DSP retains its
filter and oscillator state across omitted frames. Output indices and inline
controls follow the shortened clock. Explicit ECI pauses remain unchanged.
This replaces post-render exact-zero PCM cutting, which kept an unnecessarily
long residual decay and resumed with a distant filter state.

Validation covers 196 unchanged default-mode PCM/index cases, 315 German
rate/model/text cases at three speeds in all pause modes, 84 explicit-pause
comparisons and 63 word-control comparisons. The production SAPI backend
matches direct ECI audio in 98 language/rate cases and 52 speed cases. A
transport-only comparison retains all 104 streams while reducing Write calls
by roughly seven to fifteen times. Windows checks use in-memory streams for
784 language/rate cases per architecture, then remove both registrations.
See the [validation report](../validation/0.2.204.json) for artifact hashes and
limits.
Physical-device stutter and perceived pause quality still need listening
assessment; passing stream tests cannot establish those subjective outcomes.
