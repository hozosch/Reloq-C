# Original ECI acoustic timing comparison

The original Windows ECI.dll distributed with Eloquence_64 v25 was compared
with ReLoq at the same native voice speed, voice parameters and sample rate.
The original DLL and speech recordings are external to this repository.

For `adictive drums` at native speed 106 (NVDA's normal speed 60 in the
reference driver), both engines produced 5,500 samples at 11,025 Hz. Equal
total duration did not mean equal sound: ReLoq emitted an additional short
frication impulse around the /k/–/t/ transition.

The native language provider exposes an acoustic target stream at 1 ms
intervals. Sampling those targets on a 5 ms clock and holding each set of
targets for the next five 1 ms rendering frames reproduces the original's
timing. In this example, the resulting waveform's correlation with the
reference is greater than 0.9999; the previously emitted impulse is absent.
This holds the source controls rather than changing the overall utterance
duration, globally suppressing noise, or post-processing recorded speech.

The user found that applying this clock at all speeds made the previously
accepted slow voice sound less natural. The original still uses the 5 ms
clock at those speeds; matching it is not sufficient to preserve that voice.
The shared renderer therefore keeps 1 ms interpolation up through native
VS95 (normal NVDA 50), blends the controls continuously through VS106, and
uses the reference 5 ms clock from VS106 (normal NVDA 60). The blend uses
the native duration factor, also for VWPM; it is independent of host and
tag syntax. Intra-utterance changes transition over 20 ms.

The same comparison covered seven test texts in six languages/dialects,
two speeds, two voice genders and both original sample rates (8 and 11.025
kHz): 56 combinations. The 10 ms amplitude-envelope error decreased in all
56 cases. The comparisons do not establish equality for every language,
phoneme, voice, or extended output sample rate.

`tests/data/original_acoustic_clock_enu.json` retains only 10 ms RMS values
for four English cases; `nvda/test_eci_high_speed_reference.py` checks the
fast cases against them. `nvda/test_eci_slow_speed_reference.py` checks the
slower voice against numeric envelopes measured before the 5 ms change.
Larger reference measurements are generated by the two timing observation
tools. Callback sizes of 110 and 1,100 samples and optional original phoneme
callbacks produced identical PCM.

ECI `vs` commands are sent to the same native duration planner as voice-speed
settings. Previously, some languages approximated a tag by stretching the
renderer timeline after planning, which did not reproduce per-phone timing.
`nvda/test_eci_speed_setting.py` compares the actual PCM for setters, tags,
queued changes and representative extended sample rates. Existing WPM and
Hertz tests cover their corresponding settings and tags independently.
